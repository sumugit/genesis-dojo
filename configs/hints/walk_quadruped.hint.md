四足歩行（Go2が4本足で、立ったまま前へ歩く）の設計上のヒント（人が書いた助言）:

よくある失敗（変な歩き方）: 「進んだ距離」「前進速度」だけを報酬にすると、足を引きずる、跳ねる（4本とも宙に浮く）、体を傾けて滑る、片側だけの足で進む、という方策が勝ちます。歩き方そのものを報酬にしてください。

歩き方の設計:
- 対角の2本を組にして交互に踏み出す（トロット）。FL と RR を組、FR と RL を組にする。足の並び順は feet_pos の FL, FR, RL, RR。
- 観測には周期1.5Hz の sin/cos（時計）が入っている（入っていなければ、時計なしで足の高さの交互だけを報酬にする）。報酬側でも位相 phase = 2π·1.5·s.episode_time を使い、sin(phase) > 0 の間は FL・RR を遊脚（持ち上げる）、FR・RL を支持脚（接地）にする。sin(phase) < 0 の間は逆。足の高さが予定に合うほど報酬、合わなければ小さな罰にする。
- 遊脚の足先の高さは 0.06〜0.10 m（接地中の足先は約 0.023 m）。持ち上げすぎると転ぶ。支持脚は 0.04 m 以下。
- 少なくとも2本は常に接地させる。4本とも持ち上がる（跳ねる）ことには罰をかける。
- 前進は、胴体の前向きの速度 s.lin_vel_b[:, 0] を 0.3〜0.6 m/s の目標に近づける項（exp(-(v-v目標)²/σ²) の形）にする。横方向の速度 s.lin_vel_b[:, 1] とヨー角速度 s.ang_vel_b[:, 2] は小さく保ち、まっすぐ進ませる。進んだ距離そのものを大きくする報酬は使わない。

姿勢と安定:
- 胴体の高さ s.base_pos[:, 2] は 0.26〜0.32 m（立位は約 0.29 m）を保つ。nose_up_angle と roll_angle は小さく（±0.2 rad 以内）保つ。
- 動作の滑らかさのため、行動の変化（s.actions - s.last_actions）と関節速度に、小さな罰をかける。罰が大きすぎると動かなくなるので、重みは小さく。
- 打ち切り（failed）は、転倒（胴体が低い、横転）など明らかな失敗に限る。厳しすぎると学習が進まない。

重みの目安: 主要な項（歩き方の予定、姿勢）を大きく、前進速度の項はそれより弱く、滑らかさの罰は最も小さくする。まず立ち続けることを優先し、歩きは立てたときだけ効くようにゲートするとよい。
